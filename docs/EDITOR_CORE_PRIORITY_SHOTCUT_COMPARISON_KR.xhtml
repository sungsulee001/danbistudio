편집기 우선 개선 판단 기록

Shotcut 소스와 Danbi Studio 현재 Editor 상태를 비교한 뒤, 편집기 핵심 조작을 우선 끌어올려야 한다는 판단을 기록한다.

결론: Danbi Studio는 AI orchestration, ComfyUI, Automation, Render Worker, Plugin 구조가 강점이지만, 순수 편집기 품질은 아직 Shotcut 수준이 아니다. 편집기 기능이 탄탄해야 나머지 AI/자동화/렌더 구조의 의미가 살아난다.

Shotcut 대비 현재 수준

영역 Shotcut Danbi 현재
Timeline QML 기반 전용 timeline, multitrack model, timeline commands 기본 clip move, trim, selection은 있으나 작업감과 안정성은 더 다듬어야 한다.
Monitor 조작 Filter VUI, crop, size-position, keyframe 연동 구조 Program Monitor 조작은 부분 구현 상태다. Move는 동작하지만 scale/rotate drag 검증이 실패했다.
Keyframes 별도 Keyframes dock/model과 filter keyframe 체계 Keyframe 기능은 있으나 상용 편집기 수준의 직접 조작 UX는 부족하다.
Filters MLT filter metadata, Filters dock, QML filter UI 다수 Inspector effects는 있으나 필터 탐색/적용/조정 경험은 Shotcut보다 얕다.
Export / Jobs Encode dock, Jobs dock, MLT 기반 안정성 Danbi도 render/export 구조는 있으나 Editor 조작 UX와의 통합 완성도가 더 필요하다.
편집기 UX 오래 사용된 NLE 구조 최근 재배치 단계이며 아직 “편집기 손맛”은 부족하다.

현재 blocker급 차이

  • Program Monitor transform handle 기본 노출이 약하다.
  • Scale/rotate handle은 보이지만 실제 drag 동작 검증에 실패했다.
  • Waveform 직접 편집이 없다.
  • Timeline은 가능하지만 작업감, 피드백, snap/ripple/trim UX를 더 끌어올려야 한다.
  • UI는 상용 편집기 형태로 가까워졌지만 실제 마우스 편집 감각은 아직 Shotcut급이 아니다.

우선순위 결정

다음 구현 우선순위는 UI 장식이나 새 AI 기능이 아니라 편집기 핵심 조작이다.

  1. Program Monitor transform overlay 기본 노출과 직접 조작 안정화
  2. Scale/rotate handle drag 실제 동작 보장
  3. Timeline trim/move/scrub/zoom 피드백 강화
  4. Keyframe이 있는 clip의 직접 조작 정책 정리
  5. Waveform interaction 또는 최소한 waveform 기반 edit affordance 설계

작업 원칙: Danbi Studio는 AI 제작 플랫폼이지만, 편집기가 먼저 탄탄해야 한다. 편집이 불편하면 ComfyUI, Automation, Render Worker, Plugin 시스템의 체감 가치도 떨어진다.
