핵심 결론

toobusy_pingpong은 영상 편집기가 아니라 Telegram, LM Studio, ComfyUI, 로컬 대시보드를 묶은 로컬 AI 생성 오케스트레이터다. Danbi에는 이미 ComfyUI client, workflow loader, queue, AI Studio가 있으므로 통째 이식보다 안정성/진단/워크플로우 등록 기능을 흡수하는 방식이 맞다.

가장 먼저 적용할 부분은 ComfyUI readiness, WebSocket 진행률, interrupt/free memory, workflow analyzer, 결과 파일 fallback이다. Telegram 봇은 제품 핵심 흐름과 거리가 있어 후순위로 둔다.

적용 설계 카드

1. Readiness

/system_stats, /object_info, workflow JSON class/model reference를 검사해 AI Studio에서 Ready/Missing을 표시한다.

2. Progress

ComfyUI WebSocket 이벤트를 queue snapshot에 저장해 sampling %, executing node, error message를 보여준다.

3. Result Fallback

로컬 output path 복사가 실패하면 ComfyUI /view로 bytes를 받아 Danbi output storage에 저장한다.

4. Workflow Analyzer

API-format JSON에서 prompt, seed, image, output, ratio, dimension 후보를 추정해 preset metadata로 저장한다.

5. Prompt Enhancer

LM Studio OpenAI-compatible API를 선택 기능으로 연결하되, 모델 load/unload와 VRAM 해제는 명시적 설정으로 둔다.

6. Telegram Later

Telegram state machine과 file send는 본체보다 webhook 또는 remote-control plugin 후보로 남긴다.

구현 로드맵

  1. 1단계: ComfyUIClient에 /object_info, /queue, /interrupt, /free, /view 메서드 추가. readiness API와 AI Studio 상태 표시 추가.
  2. 2단계: queue 실행 시 WebSocket progress 수신. polling fallback 유지. snapshot에 stage/current node/progress 저장.
  3. 3단계: workflow JSON analyzer 추가. prompt/negative/seed/output/model/ratio 후보 추정 테스트 작성.
  4. 4단계: AI Studio에 readiness badge, model override, result metadata 비교, 안전한 asset state action 추가.
  5. 5단계: LM Studio와 Telegram은 선택 기능 또는 plugin으로 분리 검토.

최종 판단

Danbi에 가장 유용한 부분은 Telegram 봇이 아니라 운영 안정성이다. 실행 전 진단, 실행 중 진행률, 실패 시 결과 회수, workflow 등록 자동화, 선택형 프롬프트 보강을 먼저 적용하고 Telegram은 후순위 remote adapter로 분리하는 것이 맞다.
