# P5. 파이프라인 컨트롤 센터 — UX 화면 구조 (IA)

> 작성: 2026-07-06 · 와이어프레임 시각화: [../UX_CONTROL_CENTER_WIREFRAME_KR.html](../UX_CONTROL_CENTER_WIREFRAME_KR.html)
> 상위 결정: [../ARCHITECTURE_DECISION_KR.html](../ARCHITECTURE_DECISION_KR.html) — "한 곳에서 다 제어" 요구에 따라 Danbi Studio를 파이프라인 컨트롤 센터로 확장. 단, **UI와 버튼만 들어가고 두뇌(LLM·업로드 실행)는 밖**.

---

## 1. 목적과 범위

- **목적**: 사용자가 프로그램을 오가지 않고 Danbi Studio 한 곳에서 시나리오 승인부터 업로드 현황까지 전 공정을 보고 제어하는 화면 구조(정보 구조·동선·데이터 매핑)를 확정한다.
- **범위**: 화면 목록, 화면별 구성 요소와 데이터 출처, 게이트 인터랙션, 탭 간 동선. **비주얼 디자인(색·타이포)과 코드 구현은 범위 밖** — 구현 시 `frontend-design` 스킬로 별도 진행.
- **위치 [제안]**: Danbi 신규 워크스페이스 `/production`. 기존 상단 모드 바에 `Production` 모드 추가(기존 Editor 모드와 병렬). [08 통합 빌더](./08_UNIFIED_BUILDER_KR.md)와 [09 대시보드](./09_COMFYUI_DASHBOARD_KR.md)는 이 워크스페이스의 탭 2·3으로 흡수된다(문서의 화면 설계는 유효, 호스팅 위치만 통합).

## 2. 컨트롤 센터의 3대 UI 원칙 (전 화면 공통 계약)

1. **읽기·표시·상태 전이·트리거까지만.** UI가 하는 쓰기는 딱 3종: ① frontmatter `status` 전이 ② revise 코멘트 추가 ③ 오케스트레이터 트리거 요청. LLM 호출·업로드 실행 코드는 UI에 없다.
2. **데이터 출처는 3계통뿐**: `VAULT`(마크다운 직접 읽기/쓰기 — Electron 로컬 파일 접근), `API`(Danbi 자체 `/api/editor/*`), `EXT`(외부 모듈 상태 파일 — 업로더 등). 각 화면 요소는 반드시 이 중 하나에 매핑된다(§4 표).
3. **게이트는 눈에 보이게.** 인간 승인 게이트 4개(시나리오·콘티·편집본·게시)는 화면마다 같은 위치(우측 패널 상단)·같은 모양의 승인 버튼으로 통일. 승인은 되돌리지 않는다 — 잘못 승인했으면 revise 코멘트로 재작업 지시(상태 머신 규약과 동일).

## 3. 정보 구조 (IA)

```
Danbi Studio 상단 모드 바:  [ Editor ]  [ Production ★신규 ]  [ AI Studio ]  …

Production 워크스페이스
├── 글로벌 컨텍스트 바 (전 탭 공통 고정)
│   ├── 프로덕션 선택기: 20-productions/ 폴더 스캔 드롭다운 + [+ 새 영상]
│   └── 단계 스테퍼: S1───S2───S3───S4·5───S6───S7  (status 기반 진행 표시)
│
├── 탭 0  🏠 오늘        ← 기본 진입. "지금 내가 할 일"
├── 탭 1  📝 기획        ← S1 시나리오 · S2 대본 읽기/승인/반려
├── 탭 2  🎞️ 콘티·에셋   ← S3~S5 검수 (= 08 통합 빌더 흡수)
├── 탭 3  ⚡ 생성 큐      ← ComfyUI 상태·큐·갤러리 (= 09 대시보드 흡수)
├── 탭 4  ✂️ 편집        ← 기존 편집기로 딥링크 + 검수 완료 처리
└── 탭 5  🚀 배포        ← S7 업로드 현황 · 성과 · 회고
```

- **동선의 기본형**: 홈의 "할 일 카드"를 클릭하면 해당 프로덕션+해당 탭으로 바로 이동한다. 탭을 순서대로 도는 게 아니라 **홈이 라우터**다.
- 단계 스테퍼는 현재 프로덕션의 `status`와 잡 스냅샷으로 계산한다. 클릭 시 해당 단계 담당 탭으로 이동.

|---|---|---|
| 승인 대기 (최상단, 가장 크게) | 게이트별 대기 카드: "시나리오 2건 승인 대기", "콘티 CUT 6개 검수 대기", "편집본 1건 검수", "게시 승인 1건" — 클릭 시 해당 탭 이동 | `VAULT` (status/approval 필드 스캔) |

## 5. 게이트 인터랙션 규약 (전 화면 통일)

1. 승인 버튼은 **우측 패널 최상단 고정**, 전 탭 동일한 형태(초록·자물쇠 아이콘). 비활성 조건을 버튼 아래 한 줄로 항상 표기(예: "미검토 컷 3개").
2. 승인 = 확인 다이얼로그(후속 자동 동작 명시) → status 전이 → `log.md` append → 스테퍼 갱신. **승인 취소 기능은 만들지 않는다** — 재작업은 revise 코멘트로.
3. 반려 = 사유 입력 필수. 사유는 revise 코멘트로 문서에 기록되어 에이전트 재작성 입력이 된다 [사실 — S2 규약].
4. `EXTERNAL_PENDING`은 버튼이 아니라 **회색 배지 + 남은 절차 설명 툴팁**. 사용자가 앱 안에서 할 수 있는 일이 없음을 명확히.
5. 실패·blocked는 빨강 카드로 홈에 승격. 카드에는 항상 "다음 행동" 1개를 제시(재시도/문서 열기/로그 보기).

## 6. 구현 기술 (코드 없이)

- **호스팅**: Next.js 신규 라우트 `/production` + 탭 라우팅. 기존 상단 모드 바 확장 [사실 — 모드 바 존재].
- **vault 접근**: Electron main의 파일 API로 vault 루트를 읽고(경로는 설정에서 지정), frontmatter 파싱·패치는 main 프로세스 담당(원자적 쓰기: temp→rename [사실 — 지식 DB 규약]). 렌더러는 IPC로만 접근 — 기존 boundary guard 관행 유지.
- **폴링 주기 [제안]**: vault 스캔은 파일워처(chokidar류) 이벤트 기반, 잡 스냅샷은 기존 렌더러 폴링 관행(수 초) 재사용.
- **트리거**: 오케스트레이터 요청 파일(`DanbiVault/.requests/` 등)에 기록 → 오케스트레이터가 수거. Danbi가 LLM 프로세스를 직접 spawn하지 않는다.
- **스키마 결합 최소화**: UI가 아는 vault 필드는 [10 지식 DB](./10_KNOWLEDGE_DB_KR.md) frontmatter 계약 + `schema_version`뿐. 버전 불일치 시 읽기 전용 모드로 강등 [제안].

## 7. 활용 스킬

- 설계·계획: `feature-planner`, superpowers `writing-plans`
- UI 구현: `frontend-design`(레이아웃·컴포넌트), `theme-factory`(기존 에디터 다크 테마와 통일)
- 검증: `webapp-testing`(탭별 E2E — 승인 게이트 우회 불가 반증 테스트 포함), superpowers `test-driven-development`
- 코드 탐색: Serena (기존 모드 바·3열 레이아웃·AI Result Review 컴포넌트 재사용 지점 탐색)

## 8. 구현 단계 체크리스트

**선행 조건**: vault 스키마 확정(P3), 08·09 문서의 화면 설계 확정, 오케스트레이터 트리거 방식 합의(P4).

1. `/production` 셸 + 글로벌 컨텍스트 바(프로덕션 선택기·스테퍼) — 검증: 폴더 스캔으로 프로덕션 목록 표시
2. 탭 0 홈 — 검증: status 스캔으로 승인 대기 카드가 정확히 집계, 카드 클릭 라우팅
3. 탭 1 기획 — 검증: 승인 버튼이 frontmatter만 바꾸고 본문 무손상, revise 코멘트 기록, `draft→approved` 외 전이 불가
4. 탭 2·3 — 08·09 문서 체크리스트를 이 워크스페이스 안에서 수행
5. 탭 4 편집 — 검증: 딥링크로 프로젝트 열림, 검수 완료 시 전이+enqueue가 각 1회만 발생
6. 탭 5 배포 — 검증: 업로더 상태 파일 미존재 시에도 화면 성립(수동 업로드 안내 폴백)
7. 통합 E2E: 샘플 프로덕션 1건을 홈→기획 승인→컷 승인→편집 검수→게시 승인까지 클릭만으로 통과

## 9. 완료 조건

**기계(에이전트) 완료조건**: ① 7개 체크리스트 항목의 검증 통과 ② 승인 게이트 우회 불가 테스트 통과 ③ vault에 UI가 쓰는 필드가 status·revise·요청 파일 3종뿐임을 확인 ④ 기존 편집기 E2E 무회귀 ⑤ lint/테스트/`architecture:check` 통과.
**EXTERNAL_PENDING**: 실사용 UX 검수(탭 동선이 실제로 "한 곳 제어"로 느껴지는지), 비주얼 디자인 승인, Fresh Windows 수락 테스트.
