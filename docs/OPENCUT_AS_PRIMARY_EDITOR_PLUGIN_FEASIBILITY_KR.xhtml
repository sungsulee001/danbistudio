OpenCut 주 편집기 전환 및 Danbi 플러그인화 가능성 점검

작성일: 2026-06-19 / 범위: 문서 검토만 수행, 코드 구현 없음

요청 내용은 OpenCut을 Danbi Studio의 주 편집기로 사용하고, Danbi의 AI Studio, Automation, Render Queue, Extension, Settings, ComfyUI, 렌더 워커 계열 기능을 플러그인 또는 외부 기능 형태로 얹을 수 있는지 점검하는 것이다.

최종 판단 조건부 가능

기술적으로는 가능하지만 현재 릴리즈 후보의 즉시 전환 대상으로는 부적합하다.

단기 권장안 Reference-only

OpenCut은 편집기 상호작용 참고 대상으로 사용하고 Danbi 편집기를 개선한다.

장기 가능안 Adapter spike

별도 브랜치에서 OpenCut 어댑터와 Danbi Bridge API를 검증한다.

금지선 No migration

OpenCut 전체 migration이나 Danbi 오케스트레이션 축소는 이번 범위가 아니다.

외부 상태 확인

대상 확인 내용 판단
OpenCut main 공개 README 기준으로 OpenCut main은 ground-up rewrite 중이다. 예정 항목은 Editor API, first-class third party plugins, Rust core 기반 desktop/mobile/browser, MCP server, headless mode, scripting tab이다. 미성숙 플러그인-first 방향은 Danbi와 맞지만 아직 당장 붙일 안정 API로 보기는 어렵다.
OpenCut classic 기존 앱 코드이며 README는 original codebase이고 archived/no longer maintained라고 명시한다. GitHub 저장소도 2026-05-17 archive/read-only 상태다. 참고 가능 편집기 상호작용 참조에는 유용하지만 Danbi의 장기 의존 호스트로 삼기에는 유지보수 위험이 크다.
라이선스 OpenCut main/classic 모두 MIT 라이선스다. 사용 가능 라이선스 자체는 통합을 막지 않는다. 단, NOTICE/출처/변경사항 표기는 필요하다.

결론

OpenCut을 Danbi Studio의 주 편집기로 직접 교체하고 Danbi의 나머지 기능을 전부 OpenCut 플러그인으로 옮기는 것은 기술적으로 불가능하지는 않지만 제품 재플랫폼 수준이다. 특히 Danbi의 ComfyUI 배치 큐, AI Results, Automation Hooks, Render Worker, Render Worker Daemon, Fleet Discovery, Headless Render, Extension/Plugin system은 단순 UI 플러그인이 아니라 프로젝트 스키마, 렌더 preflight, 저장 경로, 작업 큐, 보안 서명, 외부 프로세스 실행 경계에 결합되어 있다.

단기 방향은 OpenCut classic의 timeline/monitor interaction 패턴을 참고하여 Danbi editor core를 끌어올리는 것이다. 중장기 방향은 OpenCut main의 Editor API와 plugin-first 구조가 실제로 안정화된 후, 별도 브랜치에서 Danbi Bridge API를 통해 제한된 통합 spike를 검증하는 것이다.

통합 모델별 판단

모델 설명 가능성 주요 리스크 권장 여부
1. Reference-only OpenCut을 실행 의존성으로 두지 않고 timeline, trim, drag/drop, preview overlay, transform handle 구조를 Danbi 구현에 참고한다. 높음 Danbi 쪽 상호작용 구현 품질을 계속 직접 개선해야 한다. 단기 권장
2. OpenCut classic embed OpenCut classic의 web editor를 Danbi Electron 내부 route/webview로 넣고 Danbi 기능을 IPC/HTTP bridge로 호출한다. 가능하지만 고비용 classic은 archive/read-only이며 Danbi 플러그인 호스트로 설계되어 있지 않다. Electron 보안, 파일 접근, 프로젝트 저장, export preflight를 새로 맞춰야 한다. 제품 릴리즈 후보에는 비권장
3. OpenCut main 기반 장기 전환 OpenCut main rewrite의 Editor API/plugin-first 구조가 안정화된 뒤 Danbi 기능을 OpenCut 플러그인 또는 extension으로 제공한다. 미래 조건부 현재 API가 예정 상태라 실제 플러그인 계약, 렌더 계약, asset 계약을 확인할 수 없다. 지금 의존하면 Danbi 릴리즈 일정이 OpenCut rewrite 일정에 묶인다. 장기 관찰 및 spike 후보
4. Danbi editor 완전 제거 후 OpenCut 교체 Danbi 편집 UI와 project/timeline runtime을 OpenCut으로 대체하고 Danbi 기능을 전부 외부 플러그인으로 분리한다. 고위험 Danbi의 스키마, preflight, render worker, ComfyUI state, plugin signing, local installed-app acceptance를 모두 재검증해야 한다. 금지에 가까움

Danbi 기능을 플러그인화할 수 있는가

Danbi 기능 OpenCut 호스트에서 플러그인화 가능성 필수 조건 판정
ComfyUI integration 가능은 하다. 다만 단순 메뉴 플러그인이 아니라 asset 생성, pending/generating/generated/failed 상태, timeline replacement, effect pass, 결과 검수 UI가 필요하다. OpenCut이 media asset 등록, timeline insert/replace, clip generation metadata, job status panel, render preflight hook을 노출해야 한다. 조건부 가능
ComfyUI batch queue Danbi 쪽 큐를 외부 worker/service로 유지하고 OpenCut UI가 bridge API를 호출하는 구조가 현실적이다. queue snapshot, cancel/retry, priority, concurrency, result asset import 계약이 필요하다. Danbi-side 유지 권장
AI Results workflow 후보 asset review와 apply/replace/effect-pass 작업은 plugin panel로 가능하다. OpenCut 선택 clip과 Danbi result lineage를 연결하는 clip identity mapping이 필요하다. 어댑터 필요
Automation hooks 외부 automation plugin으로 가능하다. 단, hook event가 OpenCut timeline event와 Danbi automation event를 동시에 이해해야 한다. manual, on-import, before-export, on-gap 이벤트와 payload schema bridge가 필요하다. 어댑터 필요
Render Worker / Daemon / Fleet Discovery OpenCut 내부 플러그인으로 옮기는 것보다 Danbi render service로 두고 OpenCut editor가 render request만 보내는 구조가 낫다. OpenCut scene snapshot을 Danbi render graph 또는 공통 intermediate timeline으로 변환해야 한다. 외부 서비스 유지
Headless Render Danbi headless pipeline을 유지하고 OpenCut 쪽은 export plan provider 역할만 하는 것이 안전하다. headless에서 UI 없이 동일 timeline/effect/motion 결과를 재현하는 render parity 계약이 필요하다. 강한 계약 필요
Extension / Plugin system Danbi는 이미 manifest, permission, contribution, signature, reviewed command API, exporter writer trust를 가진다. 이를 OpenCut 내부 plugin API로 그대로 이식하려면 이중 플러그인 호스트가 된다. Danbi plugin은 Danbi host에서 실행하고 OpenCut은 bridge client로 제한하는 것이 보안상 안전하다. Danbi host 유지 권장
Export validation semantics 단순 플러그인화 위험이 가장 크다. ComfyUI pending asset, renderPath, missing media, output path, codec/container 검증이 모두 보존되어야 한다. OpenCut export UI가 Danbi preflight result를 그대로 표시하고, blocked/warning semantics를 변경하지 않아야 한다. 직접 이식 비권장

Danbi와 OpenCut 스키마 차이

항목 Danbi OpenCut classic 통합 영향
프로젝트 구조 EditorProject가 assets, tracks, captions, markers, automation, plugins, exportProfiles를 직접 포함한다. scene 중심 구조다. SceneTracks는 overlay, main, audio로 분리되고 각 track이 elements를 가진다. 1:1 교체가 아니라 bidirectional mapper가 필요하다. Danbi tracks와 OpenCut overlay/main/audio의 의미가 다르다.
클립/엘리먼트 TimelineClip은 kind, start, duration, sourceIn, speed, volume, opacity, blendMode, automationTags, effects, keyframes, transition, generation을 가진다. TimelineElement는 type, startTime, duration, trimStart, trimEnd, params, animations, effects, masks를 가진다. sourceIn/trimStart, keyframes/animations, generation metadata의 변환 규칙을 만들어야 한다.
미디어 경로 packaged Electron에서는 import/cache/projects/packages/jobs/stt/autosave/renders/outputs/temp가 userData 아래여야 한다. asset은 preview용 source와 FFmpeg용 renderPath를 분리한다. web app 중심 구조라 file/import/storage 계약이 Danbi Electron userData 정책과 다르다. OpenCut을 쓰더라도 Danbi storage provider가 authoritative해야 한다. Program Files 쓰기 금지는 Danbi bridge가 보장해야 한다.
렌더 FFmpeg render graph, render preflight, render worker, queued/headless/fleet flow가 존재한다. classic은 web editor와 renderer service/WASM 방향의 자체 구조가 있다. 미리보기 엔진을 가져와도 최종 export는 Danbi render graph와 parity를 맞추지 않으면 릴리즈 blocker가 된다.
플러그인 보안 Danbi extension API는 filesystem/network/comfyui/render/project permission과 manifest signature/trust 정책을 가진다. classic에는 Danbi와 호환되는 plugin sandbox boundary가 없다. OpenCut 내부에서 Danbi plugin을 직접 실행하지 말고 Danbi main process/extension runtime으로 우회해야 한다.

OpenCut에서 코드 이식 가능한 영역

OpenCut 전체 migration은 금지한다. 아래는 Danbi editor core 품질 향상을 위해 참고 또는 부분 이식 가능한 영역이다.

영역 OpenCut classic 참조 파일 Danbi 적용 방식 주의점
Timeline drag/move timeline/controllers/element-interaction-controller.ts, timeline/group-move/*, timeline/components/drop-target.ts drag threshold, selected group move, snap, drop target, new track fallback 패턴을 Danbi timeline controller로 재해석한다. OpenCut의 MediaTime/track model을 그대로 가져오면 Danbi seconds 기반 timeline과 충돌한다.
Timeline drag/drop import timeline/controllers/drag-drop-controller.ts, timeline/hooks/use-timeline-drag-drop.ts media bin에서 timeline으로 바로 끌어놓는 interaction model을 참고한다. Danbi packaged Electron import는 반드시 userData 저장 경로와 renderPath rewrite를 거쳐야 한다.
Transform direct manipulation preview/controllers/preview-interaction-controller.ts, preview/controllers/transform-handle-controller.ts, preview/hooks/use-preview-interaction.ts preview hit-test, move preview, commit/discard, scale/rotate handles, snap line 구조를 Danbi Program Monitor에 맞춘다. Danbi render parity를 위해 motion effect/keyframe 저장 방식과 FFmpeg output이 같이 맞아야 한다.
Preview overlay commit model core/managers/timeline-manager.ts의 previewElements, commitPreview, discardPreview 드래그 중에는 draft overlay로 즉시 미리보기하고 pointer up 때 undo 가능한 command로 commit하는 패턴을 유지한다. Danbi의 undo/redo, autosave, render preflight dirty state와 연결해야 한다.
Command pattern commands/base-command.ts, commands/timeline/element/*.ts split, move, insert, duplicate, update-effects 같은 편집 action을 command 단위로 정리하는 참고 자료로 쓴다. Danbi의 automationTags, generation binding, plugin metadata를 command가 보존해야 한다.

필수 선행 계약

OpenCut을 실제 편집기로 사용하려면 UI부터 바꾸면 안 된다. 아래 계약이 먼저 있어야 Danbi 기능을 플러그인 또는 bridge로 붙일 수 있다.

  1. Project/timeline interchange contract: OpenCut SceneTracks/TimelineElement와 Danbi EditorProject/TimelineClip의 왕복 변환.
  2. Asset registry contract: source, renderPath, thumbnail/proxy/waveform cache, missing media relink, packaged userData 저장 정책.
  3. Editor command bridge: insert, trim, split, move, select, replace, apply effect, apply transition, apply caption, apply marker.
  4. Preview/render parity contract: preview에서 보이는 motion/crop/effect/caption/mask 결과가 Danbi FFmpeg render와 일치해야 한다.
  5. Job bridge contract: ComfyUI, STT, media cache, render queue, headless render job의 status/event/cancel/retry/update payload.
  6. Plugin host boundary: Danbi plugin은 Danbi signed runtime에서 실행하고 OpenCut은 command client로만 접근한다.
  7. Export validation contract: Danbi preflight의 blocker/warning semantics를 OpenCut export UI가 변경 없이 표시하고 차단해야 한다.
  8. Installed app storage contract: packaged Electron에서는 Program Files 내부 쓰기가 없어야 하며 모든 mutable storage는 userData/AppData 아래여야 한다.

프로토타입을 한다면

프로토타입은 제품 브랜치가 아니라 별도 spike에서 제한적으로 해야 한다. 목표는 OpenCut으로 Danbi 전체 기능을 옮기는 것이 아니라 bridge 계약의 성립 여부를 확인하는 것이다.

단계 범위 완료 기준
1. Schema mapper video/audio/image/text clip, sourceIn/trim, basic transform만 왕복 변환한다. Danbi sample project 일부를 OpenCut view model로 변환하고 다시 Danbi project로 돌아와 차이가 설명 가능하다.
2. Storage bridge OpenCut import 요청을 Danbi Electron main의 import/storage path로 통과시킨다. Program Files 쓰기 없이 userData 아래에 import/cache/renderPath가 생성된다.
3. Basic timeline edit bridge insert, move, trim, split, select만 연결한다. OpenCut UI 조작이 Danbi EditorProject 변경으로 반영되고 undo/redo가 깨지지 않는다.
4. Render bridge OpenCut 편집 결과를 Danbi export preflight와 FFmpeg render로 넘긴다. MP4 render가 생성되고 ffprobe-readable이며 preview/render 차이가 추적 가능하다.
5. AI/automation bridge ComfyUI generate now, batch queue, AI Results apply, before-export hook을 bridge로 호출한다. 기존 Danbi ComfyUI/export validation semantics가 변경되지 않는다.

명확한 비권장 사항

  • OpenCut classic을 Danbi의 장기 편집기 호스트로 직접 fork하는 것.
  • OpenCut main rewrite API가 안정화되기 전에 Danbi 릴리즈 후보를 그쪽에 묶는 것.
  • Danbi의 ComfyUI, Automation, Render Worker, Headless Render, Extension 시스템을 OpenCut UI 플러그인으로 축소하는 것.
  • Export preflight나 ComfyUI pending/generating/generated/failed 의미를 OpenCut 편집 편의성 때문에 완화하는 것.
  • OpenCut 편집 결과를 FFmpeg renderPath/userData/storage 정책 없이 바로 Danbi render에 넣는 것.

권장 로드맵

시점 권장 작업 이유
단기 Danbi editor core의 direct manipulation, timeline drag/drop, trim, media bin UX를 OpenCut/CapCut류 패턴으로 개선한다. 릴리즈 후보의 저장/렌더/ComfyUI 검증 범위를 유지하면서 편집 품질을 올릴 수 있다.
단기 Danbi Editor Bridge API 문서를 먼저 만든다. OpenCut뿐 아니라 향후 다른 편집 shell도 Danbi orchestration에 안전하게 붙일 수 있다.
중기 별도 branch에서 OpenCut classic adapter spike를 제한 기능으로만 검증한다. actual dependency가 아니라 schema/interaction feasibility 확인용이다.
장기 OpenCut main의 Editor API/plugin-first가 안정화되면 다시 평가한다. 현재 예정된 plugin-first 구조가 실제 contract로 공개되면 Danbi plugin bridge 가능성이 커진다.

최종 판정

OpenCut을 주 편집기로 바로 사용 비권장 제품 릴리즈 후보 범위에서는 위험이 너무 크다.
Danbi 기능을 모두 OpenCut 플러그인으로 이전 비권장 단순 플러그인화가 아니라 오케스트레이션 재설계다.
OpenCut 상호작용 구조를 Danbi에 참고/부분 이식 권장 현재 편집기 품질 개선에 가장 현실적이다.
OpenCut adapter spike 조건부 권장 별도 브랜치, 제한 기능, Danbi Bridge API 선행 조건에서만 진행한다.
Danbi 오케스트레이션 보존 필수 ComfyUI, automation, render worker, headless, extension runtime은 Danbi 측 authoritative system으로 유지해야 한다.
